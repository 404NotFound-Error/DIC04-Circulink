# CircuLink 三人分工（按当前进度的 2.5 周收尾）

更新时间
- 2026-03-11

当前已完成（不再作为主任务）
- 已统一数据源：Express + Prisma + PostgreSQL。
- 后端核心接口已打通：认证、分类、商品、收藏、消息、订单。
- `images` 返回格式已统一为数组。
- 基础质量已可用：`lint`、`build`、API smoke 主链路可跑通。

2.5 周目标（只做剩余收尾）
- 完成前端“真实 API 全量替换与联调”。
- 完成后端“缺口能力”与稳定性收尾（`/healthz`、限流、request id 等）。
- 完成测试最终版所需的回归、文档与交付材料。

成员分工
- 成员 A（前端负责人）
  - 全量替换样例数据，确保商品/收藏/消息/订单/个人中心走真实 API。
  - 完成发布/编辑商品流程联调（含上传后展示与错误处理）。
  - 完成消息入口权限、移动端适配、可访问性基础项（label/focus）。
- 成员 B（后端负责人）
  - 补齐后端待完成项：`/healthz`、request id、分路由限流。
  - 收敛 API 细节：状态枚举一致性、错误码一致性、边界参数校验。
  - 维护接口文档，所有字段变化当日同步到 `docs/api.md`。
- 成员 C（数据与测试负责人）
  - 固化 PostgreSQL/Prisma 环境脚本（新同学一键可跑）。
  - 维护并扩展 smoke + 手工回归清单，推动缺陷闭环。
  - 输出最终测试报告与上线前检查清单。

排期（13 个工作日）
- 第 1 周（Day 1-5）：联调收敛周
  - A：完成商品详情、收藏动作同步、消息列表/聊天、订单列表/详情真实 API 联调。
  - B：补 `/healthz` + request id；修复联调中高优先级接口问题。
  - C：整理回归用例 v1，保证每天可跑一轮核心回归。
  - 周验收：前后端主流程全通，P0=0，P1 <= 3。
- 第 2 周（Day 6-10）：质量加固周
  - A：完成发布/编辑商品与上传流程闭环，补移动端与 a11y 基础。
  - B：补限流策略、权限边界、异常路径处理，减少 500 类错误。
  - C：跑回归 v2（含异常路径），沉淀问题分级和复现步骤。
  - 周验收：`lint/build/smoke` 连续 3 天稳定通过。
- 第 3 周前半（Day 11-13）：冻结验收周
  - A：修剩余前端缺陷，完成 UI/交互最终确认。
  - B：修剩余后端缺陷并冻结接口。
  - C：执行最终回归，输出测试最终版报告。
  - 最终验收：测试最终版可演示、可回归、可交接。

每天协作机制
- 每天 15 分钟站会：昨天完成、今天计划、阻塞项与负责人。
- 每天下午 1 小时联调窗口：A+B 联调，C 同步验收并登记缺陷。
- 当日规则：新增字段/改响应结构必须同步更新文档和调用方。

完成定义（DoD）
- 合并到 `main`。
- `npm run lint` 通过。
- `npm run build` 通过。
- `npm run dev:server` 可启动且 `bash scripts/api-smoke-test.sh` 通过。
- 对应文档更新（`docs/todo.md`、`docs/api.md`、本分工文档）。

剩余高优先级清单（按你们当前仓库）
- 前端：消息入口权限、发布/编辑商品 API 闭环、用户中心 API 对接。
- 后端：`/healthz`、request id、限流策略。
- 测试：手工回归清单、关键 API 集成测试第一版、交付报告。
